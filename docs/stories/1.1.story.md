## 1. User Story

**Como** Arquitecto / Desarrollador de I-bita,
**Quiero** inicializar el proyecto Next.js (App Router + TypeScript estricto + Tailwind v4) con validación Fail-Fast de variables de entorno en `src/env.ts`, protección `server-only` y regla anti-bypass de RLS en `admin.ts`, cabeceras de seguridad OWASP y `serverExternalPackages` en `next.config.ts`, tokens de diseño WCAG 2.1 AAA (Light/Dark Mode, badge "Consorcio Friendly", toggle `ARS / USDT` y Skip Link) en `globals.css`, base SEO/GEO/AEO (`JSON-LD` `WebSite` + `Organization` y `next/font/google` con `display: 'swap'`) en `src/app/layout.tsx`, utilidades criptográficas (`AES-256-GCM` con `propertyId` como AAD) y aplicar la migración DDL completa en **Supabase Cloud (`trknmgnzjhrhtwloiaga`)** con resiliencia SSL/Pooler, extensión `btree_gist`, trigger de inmutabilidad en `ledger_entries` y políticas RLS (`CREATE POLICY`) para las 10 tablas,
**Para que** la plataforma tenga un cimiento "Zero-Simulation" donde cualquier variable faltante detenga el arranque inmediatamente, los secretos de servidor jamás se filtren al cliente, nunca se esquive RLS en acciones de usuario, y PostgreSQL bloquee físicamente las dobles reservas (`SQLSTATE 23P01`) y cualquier alteración de asientos contables (`SQLSTATE 42501`).

## 2. Acceptance Criteria (Given / When / Then)

### AC-1: Validación Fail-Fast de Variables de Entorno (`AD-2`, `NFR-3`)
* **Given** el archivo `src/env.ts` configurado con `@t3-oss/env-nextjs` y `zod`
* **When** la aplicación compila o arranca leyendo `.env.local`
* **Then** valida la presencia y formato exacto de todas las variables de entorno, aceptando tanto credenciales de Sandbox como de Producción de Mercado Pago (`.regex(/^(APP_USR|TEST)-/)`) y `MP_WEBHOOK_SECRET` de al menos 32 caracteres (`z.string().min(32)`)
* **And** si falta o es inválida cualquiera de ellas, arroja un error explícito deteniendo la ejecución (prohibido usar `process.env.X || "mock"`).

### AC-2: Migración DDL Autocontenida en Supabase Cloud con `btree_gist`, Trigger, Resiliencia SSL y Políticas RLS en las 10 Tablas (`AD-1`, `AD-3`, `AD-6`, `NFR-6`, `NFR-7`)
* **Given** la cadena de conexión `DATABASE_URL` configurada en `scripts/migrate.ts` y `scripts/gates/gate-epic-1-btree-gist.ts` con `ssl: { rejectUnauthorized: false }` y `connectionTimeoutMillis: 15000`
* **When** se aplica la migración `supabase/migrations/0001_initial_schema_and_rls.sql`
* **Then** se habilitan las extensiones `pgcrypto` y `btree_gist`, se crean las 10 tablas del modelo de datos (`profiles`, `properties`, `consortium_configs`, `ical_feeds`, `bookings`, `guest_verifications`, `porteria_passes`, `contracts`, `ledger_entries`, `contact_inquiries`) con Row-Level Security (RLS) activado y sentencias `CREATE POLICY` explícitas para **cada una de las 10 tablas**
* **And** la tabla `public.bookings` posee el constraint `no_overlapping_active_bookings EXCLUDE USING gist (property_id WITH =, daterange(check_in, check_out, '[)') WITH &&) WHERE (status NOT IN ('CANCELLED', 'EXPIRED'))`
* **And** la tabla `public.ledger_entries` posee el trigger `trg_ledger_immutable` que impide cualquier `UPDATE` o `DELETE` con `SQLSTATE 42501`.

### AC-3: Blindaje `server-only`, Regla Anti-Bypass de RLS, Criptografía `AES-256-GCM` con AAD, Performance y CSP en `next.config.ts` (`AD-5`, `NFR-1`, `NFR-4`, `NFR-5`)
* **Given** el árbol base del proyecto en `src/`
* **When** se configuran `next.config.ts` y las librerías en `src/lib/*`
* **Then** `src/lib/supabase/admin.ts` y `src/lib/crypto/aes-gcm.ts` incluyen `import "server-only";` en la línea 1
* **And** `src/lib/supabase/admin.ts` (`SUPABASE_SERVICE_ROLE_KEY`) documenta y restringe su uso **exclusivamente** a Webhooks verificados, tareas de sistema y scripts de Gate (prohibido usarlo en Server Components o Server Actions de usuario para esquivar RLS)
* **And** `encryptAccessCode(plainText: string, propertyId: string)` y `decryptAccessCode(..., propertyId: string)` usan un IV aleatorio de 12 bytes, AuthTag de 16 bytes y vinculan `propertyId` como AAD (`cipher.setAAD(Buffer.from(propertyId, "utf8"))`) para impedir ataques de sustitución de códigos cifrados entre distintas propiedades
* **And** `next.config.ts` configura `serverExternalPackages: ["pg", "node-ical", "ical-generator", "pdf-lib", "mercadopago"]` e inyecta la cabecera `Content-Security-Policy` habilitando explícitamente `https://*.supabase.co` y `wss://*.supabase.co` en `connect-src` y `https://*.supabase.co` en `img-src`.

### AC-4: Estándares de Diseño WCAG 2.1 AAA, Usabilidad y Base SEO/GEO/AEO en `globals.css`, `layout.tsx` y `page.tsx` (`NFR-1`, `NFR-9`, `NFR-10`, `UX-DR1`)
* **Given** el diseño inspirado en Airbnb Argentina (`airbnb.com.ar`) y los 3 pilares de I-bita
* **When** se renderizan `src/app/layout.tsx` y `src/app/page.tsx` con `src/app/globals.css`
* **Then** `layout.tsx` configura `lang="es-AR"`, `metadataBase: new URL(env.NEXT_PUBLIC_APP_URL)`, tipografía optimizada con `next/font/google` (`display: 'swap'` para asegurar `CLS < 0.02`), OpenGraph local, el enlace accesible por teclado `"Saltar al contenido principal"` (`Skip to main content`), el toggle global persistente de moneda `ARS / USDT` en la barra de navegación y un bloque `<script type="application/ld+json">` con los esquemas `WebSite` y `Organization` explicando la propuesta de valor de I-bita en Argentina
* **And** `globals.css` define los tokens semánticos Light/Dark Mode con contraste WCAG 2.1 AAA, incluyendo el estilo del badge de seguridad `"Consorcio Friendly / Portería Verificada"` (verde esmeralda de alta legibilidad).

### AC-5: Verification Gate 1 en Terminal (`SQLSTATE 23P01` + `SQLSTATE 42501` + AAD Check)
* **Given** el script `scripts/gates/gate-epic-1-btree-gist.ts`
* **When** se ejecuta `npx tsx scripts/gates/gate-epic-1-btree-gist.ts` en la consola

-- I-BITA — MIGRACIÓN INICIAL COMPLETA (DDL + btree_gist + Trigger + 10 Tablas RLS)

-- 1. Extensiones obligatorias
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- 2. Enumeraciones de Dominio (Idempotentes)
DO $$ BEGIN
  CREATE TYPE user_role AS ENUM ('GUEST', 'HOST', 'CONSORTIUM_ADMIN', 'SUPERADMIN');
EXCEPTION WHEN duplicate_object THEN NULL; END $$;

DO $$ BEGIN
  CREATE TYPE currency_code AS ENUM ('ARS', 'USD', 'USDT');
EXCEPTION WHEN duplicate_object THEN NULL; END $$;

DO $$ BEGIN
  CREATE TYPE booking_status AS ENUM (
    'PENDING_PAYMENT',
    'PAID_PENDING_KYC',
    'ALL_ADULTS_VERIFIED',
    'CHECKED_IN',
    'COMPLETED',

    'EXPIRED',
    'ICAL_BLOCK'
  );
EXCEPTION WHEN duplicate_object THEN NULL; END $$;

DO $$ BEGIN
  CREATE TYPE kyc_status AS ENUM ('PENDING', 'VERIFIED', 'REJECTED');
EXCEPTION WHEN duplicate_object THEN NULL; END $$;

DO $$ BEGIN
  CREATE TYPE ledger_entry_type AS ENUM (
    'GUEST_PAYMENT_ARS',

-- 11. Tabla 9: public.ledger_entries — Append-Only Ledger (FR-14, AD-6, NFR-7)
CREATE TABLE IF NOT EXISTS public.ledger_entries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  booking_id UUID NOT NULL REFERENCES public.bookings(id) ON DELETE RESTRICT,
  idempotency_key VARCHAR(140) NOT NULL UNIQUE,
  entry_type ledger_entry_type NOT NULL,
  currency currency_code NOT NULL,
  amount NUMERIC(18,6) NOT NULL,
  external_reference TEXT NOT NULL,
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE OR REPLACE FUNCTION public.prevent_ledger_mutation()
RETURNS TRIGGER AS $$
BEGIN
  RAISE EXCEPTION 'LEDGER_IMMUTABLE_VIOLATION: La tabla ledger_entries es estrictamente append-only (prohibido %)', TG_OP
    USING ERRCODE = '42501';
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_ledger_immutable ON public.ledger_entries;
CREATE TRIGGER trg_ledger_immutable
BEFORE UPDATE OR DELETE ON public.ledger_entries
FOR EACH ROW EXECUTE FUNCTION public.prevent_ledger_mutation();

-- ============================================================================
